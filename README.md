# 모루 키우기 — React Native 클릭커 게임

`docs/emberworks-네이티브앱-계획서.md`를 구현한 프로젝트입니다.
계획서 24.10이 권장한 **게임 엔진 → 저장·복구 → 화면** 순서로 Phase 1 · 3 · 2를 마쳤습니다.

계획서 3.4 원칙에 따라 생산량·비용·환생·오프라인 보상은 전부 엔진에서 계산하고,
화면은 결과만 읽습니다. 화면 코드는 `src/engine`과 `src/state`만 통해 게임에 접근합니다.

## 실행

```bash
npm install
npm start            # Expo 개발 서버
npm run android      # Android에서 실행
npm run ios          # iOS에서 실행

npm test             # 자동 테스트 245개
npm run typecheck    # strict 타입 검사
npm run simulate     # 밸런스 시뮬레이션 (계획서 6.2 페이싱 검증)
npm run assets       # 효과음·배경음악·아이콘 전부 재생성
npm run bundle:check # 기기 없이 번들이 만들어지는지 확인

# 안드로이드 APK 빌드와 설치 (한글 경로 우회를 포함해 한 번에 처리)
.\scripts\build-android.ps1 -Install
```

`npm run bundle:check`는 실기기 없이도 import·설정 오류를 잡아 줍니다.
Android·iOS 양쪽 번들이 만들어지는 것까지 확인했습니다 (각 876 / 881 모듈).

## 화면 구조 (계획서 12.2)

하단 탭 5개(`대장간 · 상점 · 주문 · 업적 · 기록`), 설정은 상단 톱니바퀴, 환생은 별도 모달입니다.
미완성 기능은 탭에 노출하지 않습니다. V1.1의 도감·유물은 기록 화면 안에 들어갑니다.

**뒤로가기는 한 단계씩만 물러납니다.** 곁화면(환생·설정·공방)은 닫으면서 대장간으로
돌아오고, 다른 탭에서는 대장간으로 옵니다. 대장간에서 더 물러날 곳이 없을 때만
안내 문구를 띄우고 2초 안에 한 번 더 누르면 종료합니다 (`src/navigation/backExit.ts`).
오프라인 보상과 튜토리얼이 떠 있는 동안에는 뒤로가기를 삼키기만 합니다 — "나중에 받기"가
실제로는 보상을 버리는 동작이라 뒤로가기에 연결하면 모르는 사이에 사라집니다.

**타격할 때마다 화면 전체를 다시 그리지 않습니다** (계획서 13.4).
게임 루프는 React 밖의 `gameStore`에서 초당 10회 돌고, 각 컴포넌트는 `useGameValue`로
필요한 값만 고릅니다. 고른 값이 실제로 바뀔 때만 그 컴포넌트가 다시 그려집니다.
모루 타격 반응도 상태가 아니라 애니메이션 값으로 처리합니다.

## 그려 넣은 도트 (계획서 4.6)

에셋 파일 없이 코드로 직접 찍은 스프라이트 18장입니다. 전부 `validateSprite` 테스트가
그리드 크기와 팔레트를 검사합니다.

| 스프라이트 | 그리드 | 수량 | 내용 |
|---|---:|---:|---|
| 화로 4단계 | 32×32 | 4 | 티어가 오를수록 불꽃이 커지고 금빛·왕실 장식이 붙습니다 |
| 모루 2종 | 32×32 | 2 | 낡은 모루 → 명장의 모루(금빛 테와 룬 각인) |
| 타격 이펙트 | 16×16 | 4 | 4프레임 스파크 애니메이션 |
| 업그레이드 아이콘 | 16×16 | 10 | 집게·견습생·풀무·화로·망치·모루·설계도·불꽃·잔불·작업대 |
| 주문 아이콘 | 16×16 | 6 | 낫·철검·곡괭이·방패·룬 대검·용비늘 망치 |
| 탭 아이콘 | 16×16 | 2 | 동전 주머니·장부 (나머지 둘은 기존 아이콘 재사용) |
| 앱 아이콘 | 32×32 | 1 | 불꽃 아래 모루 — PNG로 구워 스토어·홈 화면에 씀 |
| 일하는 모습 | 16×16 | 6 | 견습생·풀무·석탄 화로 각 2프레임 |

계획서 4.4의 "화로 불꽃 크기와 색상"은 색만 바꾸는 게 아니라 **형태가 자라도록** 만들었습니다.
색만 바뀌면 성장이 눈에 잘 띄지 않기 때문입니다. 모루도 티어 2부터 외형이 바뀝니다.

불꽃 부분은 팔레트 문자 `A`로 두어, 화로 티어 강조색(주황 → 진한 주황 → 금빛 → 하늘빛 백광)이
스프라이트를 다시 그리지 않아도 그대로 반영됩니다.

## 도트 아트 규칙 (계획서 4.6)

계획서가 아트 스타일을 도트(픽셀 아트)로 정하면서 생긴 제약을 코드에서 강제합니다.

- **원본 그리드 고정**: 아이콘 16/24, 오브젝트 32, 캐릭터 48, 배경 320×180 (`theme/pixel.ts`)
- **정수 배율만**: `getPixelScale`은 1x·2x·3x·4x만 돌려줍니다. 1.5x 같은 소수 배율은
  타입 수준에서 배제되고, 테스트가 이를 검증합니다.
- **보간 없는 렌더링**: `PixelCanvas`는 픽셀 하나를 정수 크기 View로 찍어 이미지 보간이
  개입할 여지를 없앱니다. 같은 색이 이어지는 구간은 하나로 합쳐, 32×32를 1,024개가 아니라
  수십 개의 View로 그립니다 (계획서 13.4의 렌더링 부담 원칙).
- **팔레트 제한**: 스프라이트당 16색을 넘으면 `validateSprite`가 경고합니다.
- 실제 nearest-neighbor 처리 방식은 계획서 4.6이 적어 둔 대로 Phase 4에서 실기기로 검증합니다.

**타이포그래피 절충안**도 그대로 반영했습니다 — 큰 제목·연출용 숫자만 픽셀 디스플레이 폰트
자리로 두고, 본문·설명·설정은 Noto Sans KR, 수치는 고정폭을 유지합니다.
모든 텍스트를 픽셀 폰트로 바꾸면 작은 화면에서 가독성이 떨어지기 때문입니다.

## 아직 붙이지 않은 것

- **배경 도트 4장**: 렌더 경로(`PixelBackground`)는 완성됐고 실기기 검증도 끝났지만
  그림이 아직 없어 **꺼 두었습니다** (`BACKGROUNDS`가 전부 `null`). 대장간 화면에는
  모루만 보입니다. 검증용 임시 그림은 시험 무늬가 그대로 보여서 지웠습니다.
  제작 방식은 2026-08-18에 **직접 제작(Aseprite)** 으로 확정했습니다.
  사양·무드보드·켜는 방법은 `docs/art/배경-도트-제작-가이드.md`와 `docs/art/배경-무드보드.md`에 있습니다.
- **폰트**: 픽셀 디스플레이 폰트와 Noto Sans KR을 넣을 자리(`theme/fontFamily`)만
  만들어 두었고, 지금은 플랫폼 기본 글꼴을 씁니다.
- **햅틱 실제 진동**: 코드는 연결했지만 에뮬레이터에서는 확인할 수 없어 실기기 검증이 남았습니다.
- **티어 전환 크로스페이드의 실제 청취**: 로직과 호출 시점은 테스트로 검증했지만,
  화로 티어가 오르려면 평생 누적 5만이 필요해 기기에서 귀로 확인하지는 못했습니다.
- **네이티브 프로젝트**(`android/`, `ios/`): `npx expo prebuild`로 언제든 생성됩니다.

## 저장 계층 동작

저장 순서는 계획서 8.3을 그대로 따릅니다.

```text
① 기존 primarySave 검증 → ② 정상이면 backupSave로 복사 → ③ 새 데이터를 임시 키에 기록
→ ④ 다시 읽어 파싱·필드 검증 → ⑤ 정상일 때만 primarySave로 교체
```

어느 단계에서 앱이 죽어도 `primarySave`는 마지막으로 검증을 통과한 저장본을 가리킵니다.
불러올 때는 `primary → backup` 순서로 시도하고, 백업으로 복구하면 `save_recovered`
분석 이벤트(15.1)를 남겨 화면이 복구 시점을 안내할 수 있게 합니다. 둘 다 읽을 수 없으면
상태를 만들지 않고 손상으로 보고해, 화면이 안전 초기화를 안내하도록 넘깁니다.

## 기술 선택

| 항목 | 선택 | 이유 |
|---|---|---|
| 큰 수 | `break_infinity.js` | 클릭커에 맞춰 설계된 라이브러리. 문자열 직렬화 지원 |
| 테스트 | Vitest 4 | 순수 TS 엔진에 별도 설정 없이 붙는다. 취약점 0건 |
| 큰 수 접근 | `engine/bignum.ts`만 통과 | 라이브러리 교체 시 한 파일만 고치면 된다 |
| 저장소 접근 | `StorageAdapter` 인터페이스 | AsyncStorage → SQLite·클라우드 교체를 화면 수정 없이 한다 |
| 내비게이션 | React Navigation 하단 탭 | 계획서가 Expo Router와 함께 허용한 선택지. 탭 몇 개짜리 구조에 설정이 적고 동작이 명시적이다 |
| 상태 구독 | `useSyncExternalStore` + 선택자 | 초당 10회 도는 루프가 화면 전체를 다시 그리지 않게 한다 (13.4) |

## 결정과 그 이유

**주문 비용 차감은 "즉시 차감" 방식으로 확정했습니다.**
계획서 4.3은 즉시 차감과 생산량 자동 투입 두 가지를 모두 허용합니다. 자동 투입 방식은
주문 진행도가 오프라인 보상 계산과 이중으로 얽혀 저장·복구 테스트 면이 크게 늘어나므로,
V1.0에서는 제작 시작 시 즉시 차감하고 제작 시간이 지나면 수령하는 구조로 갔습니다.
진행 바는 제작 시간이 담당합니다.

**계획서 4.3의 "경비대의 철검 → 타격력 임시 강화" 보상은 잉걸불로 대체했습니다.**
세션 임시 버프 시스템(계획서 6.4의 "현재 세션용 임시 버프")은 Phase 2에서 화면과 함께
넣는 편이 맞다고 보고 Phase 1 범위에서 뺐습니다.

**편의형 업그레이드 2종의 이름은 새로 지었습니다.**
계획서가 효과만 적어 둔 자리라 대장간 세계관에 맞춰 `잔불 화덕`(오프라인 효율),
`주문 작업대`(주문 보상)로 이름 붙였습니다. 나머지 8종은 계획서 표기 그대로입니다.

## 계획서 불일치 4건과 해결 방법

계획서를 그대로 구현했을 때 서로 맞지 않던 항목입니다. 시뮬레이션으로 확인하고 해결했습니다.

**1. "첫 업그레이드 10초"와 "첫 자동 생산 30초"가 같은 사건이었습니다.**
초급 업그레이드 중 싼 쪽이 자동 생산형(견습 대장장이)이라 두 마일스톤이 동시에 일어났습니다.
무쇠 집게를 30, 견습 대장장이를 100으로 두어 첫 구매는 타격형, 자동 생산은 그 뒤에 오게
분리했습니다. 튜토리얼(12.3)이 "첫 업그레이드 구매 → 자동 생산 확인" 순서를 안내하므로
실제 플레이어의 경험 순서와도 맞습니다.

**2. 화로 티어 1 임계값(누적 300)이 "약 5분" 목표와 맞지 않았습니다.**
누적 300은 40초 만에 넘겼습니다. 계획서 6.1이 "수치는 초기 기준이며 실제 플레이 테스트 후
조정한다"고 적어 둔 항목이라 곡선에 맞춰 `50,000 / 1e7 / 5e9`로 재설정했습니다.
이제 티어 1이 약 4분 30초, 티어 2가 약 1시간, 티어 3이 첫 환생 무렵에 옵니다.

**3. 초반 경제가 계획서의 주문 비용표보다 훨씬 빨랐습니다.**
불꽃 룬 대검(250,000 잉걸불, 첫 환생 이후)에 6분이면 도달했습니다. 업그레이드 회수 기간을
장르 표준인 200~300초대로 올려(풀무 125초 → 240초, 석탄 화로 240초 → 300초) 경제를
감속했습니다. 주문 비용표는 계획서 값을 그대로 두었고, 이제 각 주문이 의도한 시점의
단기 목표로 기능합니다.

**4. 업적을 기록 화면 안에 두면 달성 조건을 보여 줄 자리가 없었습니다.**
계획서 12.1은 기록 화면을 "업적, 평생 통계, 해금 기록"으로 정의하고 12.2는 하단 탭 4개를
정했습니다. 그런데 업적은 이름과 숫자 진행도만으로는 읽히지 않습니다 — `807 / 1만`이
무엇을 세는 숫자인지 알 수 없어 달성 조건 문구가 항목마다 필요했습니다. 13종에 모두 붙이면
한 화면에서 평생 통계와 자리를 다투게 되어, 이미 달성한 8개를 접어 두어야만 했습니다.
업적을 독립 탭으로 분리해 세 묶음(수령 대기·진행 중·달성 완료)을 모두 펼치고 조건을 함께
보여 줍니다. 하단 탭은 5개가 되었고 기록 화면에는 평생 통계만 남았습니다.
계획서 12.1·12.2도 이 결정에 맞춰 개정했습니다.

**부수 항목: 순환으로 다시 올라온 적자 주문.**
농부의 낫(500 소비 → 200 보상)처럼 잉걸불이 손해인 주문은 계획서 6.5가 정한 경제 소진
장치라 의도된 설계입니다. 다만 순환으로 다시 올라온 주문을 처음처럼 보여 주면 신규
플레이어를 오해하게 만들므로, 주문 슬롯 정보에 `isRepeat`와 `netEmber`를 넘겨
화면이 "도감 보상은 이미 받음"을 표시할 수 있게 했습니다.

  화면 표기는 반올림을 거치므로 플레이어에게는 드러나지 않습니다.

## 화면 밀도 원칙

같은 값을 두 곳에 보여 주지 않습니다. 초당 생산량과 잉걸불은 상단 재화 표시줄에만,
누적 통계는 기록 화면에만 둡니다. 대장간 화면에는 화로 상태와 모루만 남기고,
남는 세로 공간은 전부 타격 영역으로 씁니다 (계획서 14 한 손 조작).

상점 카드는 계획서 5.7이 요구하는 6개 항목을 유지하되 4줄로 압축했습니다.

```text
[아이콘] 무쇠 집게              Lv.18
타격당 36 → 38 (+5.6%)
25단계 ×2까지 7개
[ 1개 구매 · 371 ]
```

세계관 설명문은 카드에서 뺐습니다. 계획서 5.7의 표시 예시에도 설명문은 없고,
목록에서 스크롤 분량을 가장 많이 잡아먹던 요소였습니다.

## 해결한 버그: 오프라인 보상 모달에 갇힘

**증상**: 앱에 복귀해 "화로가 남긴 잉걸불" 화면이 뜨면 `받기` 버튼이 눌리지 않아
게임이 완전히 막혔습니다. `onRequestClose`도 없어 뒤로가기로도 빠져나올 수 없었습니다.

**원인**: React Native의 `<Modal transparent>`는 Android에서 별도의 Dialog 창을 만드는데,
Android 15+에서 edge-to-edge가 강제되면서 그 창의 레이아웃과 터치 영역이 어긋났습니다.
화면에는 정상으로 그려지지만 터치가 버튼까지 도달하지 못했습니다.
버튼 기준 y = 1450~1640 여섯 지점을 눌러도 모두 반응하지 않아 좌표 오차가 아님을 확인했습니다.

**수정**
- `OfflineModal`을 `<Modal>` 대신 앱 트리 안의 절대 배치 오버레이로 바꿨습니다.
  전체 화면을 덮는 카드 하나뿐이라 Dialog 창이 필요하지 않습니다.
- 같은 위험이 있던 `SettingsScreen`의 초기화 확인 모달과 `PrestigeModal`에는
  `statusBarTranslucent` · `navigationBarTranslucent`를 넣었습니다.
- 어떤 이유로든 다시 막히지 않도록 `나중에 받기` 버튼을 더했습니다.
  닫아도 보상은 사라지지 않고 다음 복귀 때 다시 계산됩니다 (계획서 7).

**검증** (에뮬레이터 Pixel_8 / API 35, 릴리스 빌드): `받기`가 정상 동작하고
잉걸불 3.05만 → 43.4만으로 40.32만이 정확히 지급됐습니다. 8시간 상한도 함께 확인했습니다
(초당 20 × 28,800초 = 57.6만 → 70% = 40.32만).

## 직접 만든 효과음 (계획서 13.1)

`scripts/generate-sounds.mjs`가 칩튠 계열 소리를 코드로 합성해 WAV로 굽습니다.
외주나 상용 팩 없이 만들어 라이선스 문제가 없고(계획서 21), 음색을 바꾸려면
그 파일의 숫자만 고치고 `npm run sounds`를 다시 돌리면 됩니다.

| 소리 | 길이 | 합성 방식 |
|---|---:|---|
| `anvil_hit` | 180ms | 잡음 파열 + 비조화 부분음(1 : 2.76 : 5.4 : 8.93)으로 금속 질감 |
| `button` | 60ms | 낮은 사각파 한 번, 반복 피로가 적게 |
| `upgrade_purchase` | 300ms | 금속 울림 뒤에 낮은 삼각파로 "소비" 느낌 |
| `order_complete` | 600ms | 3음 상승 팡파르 + 금속 광택 |
| `achievement` | 850ms | 4음 상승 + 5도 화음 |
| `prestige` | 1300ms | 저음 스윕 + 불꽃 잡음 + 후반 화음 |
| `offline_reward` | 750ms | 잉걸불이 하나씩 쌓이듯 6번 상승 |

7개 합쳐 178KB (22,050Hz 16비트 모노)라 앱 크기에 부담이 없습니다.
잡음도 씨앗을 고정해 생성해서, 다시 돌려도 항상 같은 파일이 나옵니다.

**성능**(계획서 13.4): 타격은 초당 수 회 들어옵니다. 재생기를 매번 새로 만들면 소리가
겹겹이 쌓이므로 소리마다 재생기를 하나만 두고 되감아 재생하며, 소리별 최소 간격을 둡니다.

**검증**: 에뮬레이터 로그에서 `state=PLAYING`, `AudioTrack: 3969 frames delivered`
(= 22,050Hz에서 180ms)로 `anvil_hit.wav`가 그대로 재생된 것을 확인했습니다.
소리의 "느낌"은 실기기에서 직접 들어 보셔야 합니다.

## 직접 만든 배경 음악 (계획서 13.2)

`scripts/generate-music.mjs`가 화로 티어 4단계 음악을 합성합니다.
**곡을 4개 따로 쓰지 않고 같은 곡에 악기를 하나씩 얹는 방식**입니다.
그래야 티어가 바뀔 때 크로스페이드가 자연스럽고, "같은 대장간이 자란다"는 느낌이 납니다.

96BPM · 8마디 · 20초 루프 · 16,000Hz. 화음 진행은 Am → F → C → G (i-VI-III-VII)로,
단조로 시작해 밝은 화음을 거치는 흐름이 "낡은 대장간이 자란다"는 정서와 맞습니다.

| 티어 | 화로 | 편성 |
|---:|---|---|
| 0 | 초심자의 화로 | 베이스 + 옅은 패드 |
| 1 | 타오르는 화로 | + 아르페지오 |
| 2 | 작열하는 용광로 | + 망치 리듬 + 멜로디 |
| 3 | 용염의 성화 | + 옥타브 겹침 + 저음 보강 |

드럼 대신 **망치질 소리로 2박·4박을 잡습니다** — 대장간 세계관과 박자를 같은 것으로 묶었습니다.

만들면서 고친 것 두 가지:

- **루프 이음매**: 처음에는 끝부분에 시작을 섞었는데, 그러면 되돌아간 직후에 오히려 불연속이
  생깁니다. 루프 길이보다 조금 더 길게 렌더링한 뒤 **그 여분을 앞부분에 섞는** 방향이 맞습니다.
- **클리핑**: 티어 3은 레이어가 많아 피크가 1.24까지 올라 0.06%가 잘렸습니다.
  넘칠 때만 전체를 같은 비율로 줄여(피크 0.90) 티어 간 음량 관계는 유지했습니다.

**검증**: 에뮬레이터 로그에서 `state=PLAYING`과 `buffered position=20000`(= 20초 루프)으로
음악이 재생되는 것을 확인했습니다. 4개 트랙 합쳐 2.5MB입니다.

## 앱 아이콘과 스플래시

`scripts/generate-icons.ts`가 도트 스프라이트를 그대로 확대해 PNG로 굽습니다.
아이콘만 따로 그리면 게임 화면과 인상이 어긋나므로 같은 그림·같은 팔레트를 씁니다.
PNG 인코더도 `node:zlib`만으로 직접 구현해 외부 의존성이 없습니다.

| 파일 | 크기 | 배율 | 용도 |
|---|---|---:|---|
| `icon.png` | 1024×1024 | 32배 | iOS·기본. 배경을 채워 투명부가 검게 나오지 않게 함 |
| `adaptive-icon.png` | 1024×1024 | 20배 | Android 어댑티브 전경. 잘려도 되도록 가운데 62%만 사용 |
| `splash-icon.png` | 512×512 | 12배 | 스플래시 |

1024 ÷ 32 = 32배로 딱 떨어져 정수 배율 규칙(계획서 4.6)을 지키면서 픽셀이 뭉개지지 않습니다.

**만들면서 고친 것**: 처음에는 모루 본체를 중간 명도 한 색으로 칠했더니 어두운 배경 위에서
덩어리로 보였습니다. 상단 슬래브와 받침을 밝은 면으로 바꿔 대비를 올렸습니다.
홈 화면에서는 48dp 안팎으로 줄어들어 가는 선과 낮은 대비가 사라집니다.

## 업적 목록 (업적 화면)

13개를 한 덩어리로 늘어놓으니 무엇을 봐야 할지 알 수 없었습니다.
각 항목이 이름과 설명으로 2줄씩 차지해 스크롤도 길었고,
무엇보다 **"10,000번 두드린다"고만 하고 지금 몇 번인지는 보이지 않았습니다.**
클리커에서 목표까지 얼마나 남았는지 모르는 것은 큰 손실입니다.

세 묶음으로 나눴습니다.

| 묶음 | 표시 | 이유 |
|---|---|---|
| 수령 대기 | 이름 + 설명 + 받기 버튼 | 지금 할 일이라 맨 위에 |
| 진행 중 | 이름 + `620 / 10K` + 진행 바 | 다음 목표와 남은 거리 |
| 달성 완료 | 개수만, 눌러서 펼침 | 정보는 없고 자리만 차지 |

진행 중 항목은 **목표에 가까운 순서로 정렬**해 다음에 할 일이 먼저 보입니다.

진행률은 엔진의 `getConditionProgress`가 계산합니다. 조건이 여러 개일 때는
**가장 뒤처진 조건**을 돌려줍니다 — 그것이 실제로 남은 일이기 때문입니다.
(예: 풀무 3개·석탄 화로 4개가 필요한데 풀무만 다 모았다면 석탄 화로 진행률을 보여 줍니다.)

## 해결한 버그: 주문 제작을 시작하면 앱이 죽음

**증상**: 주문 탭에서 "제작 시작"을 누르는 순간 앱이 종료됐습니다.
탭에 들어가기만 할 때는 멀쩡했습니다.

**원인**: 주문 화면 선택자가 `Date.now()`를 직접 불렀습니다.
`useSyncExternalStore`는 `getSnapshot`이 **같은 스냅샷에서 같은 값**을 돌려주기를 요구하는데,
제작이 시작되면 진행률이 호출할 때마다 달라져 React가 무한 렌더 루프로 판단합니다.
제작 전에는 진행률이 0으로 고정이라 멀쩡했고, 시작하는 순간 터진 이유가 이것입니다.

**수정**: 시각을 저장소가 소유하도록 바꿨습니다. 스냅샷에 `nowMs`를 두고 게임 루프가
갱신하며, 화면은 `snapshot.nowMs`만 봅니다. 한 렌더 안에서는 값이 고정되고,
진행 바는 루프 주기(초당 10회)로 갱신됩니다.

**재발 방지**: 저장소가 안정적인 시각을 준다는 것만 검증하면 화면이 다시 `Date.now()`를
부르는 것을 막지 못합니다. 그래서 `src/screens`와 `src/components`에 `Date.now()`가
없는지 검사하는 테스트를 함께 넣었습니다. 일부러 되돌려 실패하는 것도 확인했습니다.

**검증**: 기기에서 제작 시작 → 진행(44초 → 10초 남음) → 보상 수령 → 목록에서 제거까지
전 과정을 확인했습니다. 크래시 0건.

## 공방 — 일하는 모습 (계획서 4.4)

대장간 화면의 **공방 둘러보기** 버튼을 누르면 상점에서 산 것들이 실제로 일하는 장면이 나옵니다.
숫자만 오르는 느낌을 줄이려는 계획서 4.4의 목적을 화면에서 직접 수행하는 부분입니다.

| 구역 | 장면 |
|---|---|
| 모루 구역 | 견습 대장장이들이 왼쪽에서 모루를 두드립니다 |
| 화로 구역 | 풀무가 왼쪽에서 석탄 화로에 바람을 넣습니다 |

**배치가 곧 설명입니다.** 아이콘을 한 줄로 늘어놓지 않고 서로의 관계가 보이도록 놓았습니다.
스프라이트의 망치와 풀무 주둥이가 모두 오른쪽을 향하므로, 두드릴 대상과 바람을 받을 화로를
오른쪽에 둬야 동작이 맞아떨어집니다.

| 일꾼 | 움직임 | 프레임 간격 |
|---|---|---:|
| 견습 대장장이 | 망치를 올렸다 내린다 | 420ms |
| 풀무 | 부풀었다 눌린다 | 560ms |
| 석탄 화로 | 불꽃이 일렁인다 | 300ms |

계획서 4.6이 "2~3프레임의 간단한 애니메이션만 사용해 제작 비용을 절감한다"고 정해
각 일꾼을 **2프레임**으로만 만들었습니다.

**설계에서 정한 것**

- **자동 생산형만 세웁니다.** 이들이 자리를 비운 동안에도 일하는 존재이고,
  타격형은 플레이어가 두드리는 모루가 이미 대장간 화면에 있습니다. 테스트로 못 박았습니다.
- **21명을 다 그리지 않습니다.** 1 → 2 → 3 → 4명으로 늘리고 나머지는 `+19`로 적어,
  공방이 커진다는 인상만 단계로 전합니다.
- **프레임 간격을 서로 다르게** 뒀습니다. 같은 간격이면 셋이 한 몸처럼 움직여
  기계적으로 보입니다.
- **대장간 화면에는 버튼만** 둡니다. 타격에 집중해야 하는 화면이라 장면을 다 펼치지 않고,
  누가 일하는지만 작게 미리 보여 줍니다.

**화면 전환은 설정 화면과 같은 방식**(화면 교체)입니다. 안드로이드에서 `<Modal transparent>`가
터치를 먹은 전례가 있어 같은 위험을 피했습니다.

**성능**(계획서 13.4): 프레임 상태를 `AnimatedSprite` 안에만 두어 애니메이션이 돌아도
바깥 화면이 다시 그려지지 않습니다. 모션 줄이기 설정을 켜면 멈춥니다.

**검증**: 기기에서 견습생 21명·풀무 16대·석탄 화로 4기 상태로 두 구역이 모두 나오고,
망치가 오르내리는 것과 `+19`·`+14`·`+3` 표기를 확인했습니다.

### 쓰면서 발견해 고친 문제: 마이크 권한

`expo-audio`는 녹음 API를 포함하고 있어 **쓰지도 않는 `RECORD_AUDIO`(마이크) 권한이
자동으로 들어갔습니다.** 저장소 권한과 다른 앱 위에 그리기 권한도 함께 붙었습니다.

계획서 17.4는 "개인정보 양식과 실제 SDK 동작 불일치"를 출시 차단 조건으로 두고,
15.3은 개인정보 최소 수집을 요구합니다. `app.json`의 `blockedPermissions`로 제거했고,
설치된 APK에서 사라진 것과 소리가 여전히 나는 것을 함께 확인했습니다.

남은 권한과 이유:

| 권한 | 이유 |
|---|---|
| `VIBRATE` | 햅틱 |
| `MODIFY_AUDIO_SETTINGS` | 오디오 재생 |
| `FOREGROUND_SERVICE*`, `WAKE_LOCK` | expo-audio의 재생 세션 |
| `INTERNET`, `ACCESS_NETWORK_STATE` | React Native 기본. 앱은 어떤 서버와도 통신하지 않음 |

## 한글 경로 제약 (Windows 네이티브 빌드)

이 프로젝트는 `바탕 화면\작업물\클릭커 게임`처럼 **한글이 들어간 경로**에 있습니다.
JS 번들(`npm run bundle:check`)과 테스트는 문제없지만, **네이티브 안드로이드 빌드는 실패합니다.**

- Android Gradle Plugin이 비ASCII 프로젝트 경로를 거부합니다.
- `android.overridePathCheck=true`로 그 검사를 넘겨도, NDK의 clang이 한글이 섞인
  `-I` 경로를 처리하지 못해 `expo-modules-core`의 C++ 컴파일에서 깨집니다.
- 디렉터리 junction으로 ASCII 경로를 만들어도 Gradle이 실제 경로로 되돌려 해석해 소용없습니다.

**권장**: 프로젝트를 `C:\dev\moru` 같은 ASCII 경로로 옮기세요. 그게 유일한 근본 해결입니다.

옮기기 전까지는 `scripts/build-android.ps1`이 이 과정을 대신합니다. 경로에 비ASCII 문자가
있으면 ASCII 경로로 사본을 만들어 거기서 빌드하고, 없으면 제자리에서 그대로 빌드합니다.

```powershell
.\scriptsuild-android.ps1            # Release APK 빌드
.\scripts\build-android.ps1 -Install   # 빌드 후 연결된 기기에 설치
.\scriptsuild-android.ps1 -Variant Debug -Install
```

스크립트가 처리하는 함정 두 가지:
- `robocopy /XD`에 폴더 이름만 적으면 `node_modules` 안의 같은 이름 폴더까지 전부 빠집니다.
  전체 경로로 제외합니다.
- Windows PowerShell 5.1은 네이티브 exe가 stderr로 경고 한 줄만 흘려도 오류로 취급합니다.
  (Expo는 정상 동작 중에도 `NODE_ENV` 경고를 냅니다.) 종료 코드로만 성공을 판단합니다.
- 이전 빌드의 Gradle 데몬이 산출물을 잡고 있으면 `prebuild --clean`이 EBUSY로 실패합니다.
  데몬을 멈추고, 그래도 남으면 재시도하며 Java 프로세스까지 정리합니다.

# 폴더 구조

이 프로젝트에서 **어떤 코드가 어느 폴더에 사는지, 그리고 왜 거기 사는지**를 정리한 문서입니다.
"이 기능을 고치려면 어느 파일을 열어야 하나"를 빠르게 찾는 것이 목적입니다.

밸런스 수치·게임 규칙의 근거는 `docs/emberworks-네이티브앱-계획서.md`에 있고,
구현 현황과 완료 정의 대조는 `README.md`에 있습니다.

## 한눈에 보기

```text
클릭커 게임/
├─ App.tsx              앱 조립 — 탭 내비게이션, 모달, 서비스 연결
├─ index.js             Expo 진입점 (App.tsx를 등록만 한다)
├─ src/                 게임 본체
│  ├─ engine/             순수 계산 — 생산·비용·환생·오프라인 보상
│  ├─ data/               밸런스 수치와 도트 스프라이트 (코드가 아닌 데이터)
│  ├─ types/              게임 상태의 모양 정의
│  ├─ storage/            저장·백업·복구·마이그레이션
│  ├─ state/              게임 루프와 화면 사이의 다리
│  ├─ screens/            화면 10개 (탭 5 + 설정·공방·환생·복귀·튜토리얼)
│  ├─ components/         공통 UI와 도트 렌더러
│  ├─ services/           사운드·햅틱·분석 (플랫폼에 닿는 부분)
│  ├─ theme/              색·타이포·간격·도트 규칙
│  └─ navigation/         뒤로가기 규칙
├─ scripts/             빌드 도구 — 에셋 생성, 밸런스 시뮬레이션, APK 빌드
├─ assets/              앱 번들에 들어가는 파일 (효과음·음악·아이콘)
├─ art/                 도트 작업용 원본 (번들에 안 들어감)
└─ docs/                문서
   ├─ art/                도트 아트 제작 가이드
   └─ legal/              이용약관·개인정보처리방침 초안
```

## 의존 방향

폴더를 나눈 이유의 절반은 **의존 방향을 한쪽으로 고정하기 위해서**입니다.
아래 화살표를 거스르는 import가 생기면 분리가 무너진 것입니다.

```text
screens · components  ─→  state  ─→  storage  ─┐
        │                   │                  ├─→  engine  ─→  data  ─→  types
        └───────────────────┴──────────────────┘
                    theme · services (양쪽 어디서나 씀)
```

핵심은 **`engine/`과 `data/`가 화면을 전혀 모른다**는 점입니다.
두 폴더에는 `react`나 `react-native` import가 하나도 없어서, 게임 규칙을
기기 없이 Node에서 그대로 돌려 테스트하고 시뮬레이션할 수 있습니다.
`npm run simulate`가 실제 엔진을 그대로 돌려 밸런스를 재는 것도 이 덕분입니다.

## src/ 폴더별 설명

### `src/engine/` — 게임 규칙 (12파일, 테스트 9개)

**하는 일:** 입력을 받아 결과만 돌려주는 순수 계산. 잉걸불이 초당 얼마나 늘어나는지,
업그레이드 10개를 한 번에 사면 얼마인지, 환생하면 인장이 몇 개 나오는지를 전부 여기서 정합니다.

| 파일 | 담당 |
|---|---|
| `bignum.ts` | 큰 수 연산과 화면 표기 (1.23e15 같은 수를 다룸) |
| `production.ts` | 타격·자동 생산량과 배율 계층 |
| `upgrades.ts` | 비용 공식, 1·10·최대 구매 |
| `orders.ts` / `achievements.ts` / `prestige.ts` | 주문 제작 · 업적 · 환생 |
| `offline.ts` | 오프라인 보상, 기기 시간 조작 대응 |
| `forge.ts` / `unlock.ts` | 화로 티어 · 해금 조건 판정 |
| `state.ts` / `serialize.ts` | 상태 생성·시간 진행 · 저장 직렬화와 검증 |
| `index.ts` | **공개 API** |

**규칙:** 바깥에서는 개별 파일이 아니라 `engine/index.ts`만 import 합니다.
계산 방식을 바꿔도 화면 코드로 번지지 않게 하려는 의도적인 제약입니다.

**여는 때:** 수치가 이상하게 나올 때, 새 계산 규칙을 추가할 때.

### `src/data/` — 밸런스와 그림 데이터 (10파일)

**하는 일:** 코드를 고치지 않고 바꿀 수 있는 값만 모읍니다.
`balance.ts`의 성장률, `upgrades.ts`·`orders.ts`·`achievements.ts`의 목록,
그리고 **문자 행렬로 찍은 도트 스프라이트**(`sprites.ts`, `icons.ts`, `workers.ts`)가 여기 있습니다.

스프라이트가 이미지 파일이 아니라 데이터인 이유는, 화로 티어 강조색이 바뀔 때
같은 그림을 다시 그리지 않고 팔레트 글자 하나(`A`)만 덮어쓰면 되기 때문입니다.

**여는 때:** 밸런스 패치, 업그레이드·주문·업적 추가, 도트 그림 수정.

### `src/types/` — 상태의 모양

`GameState`가 어떤 필드를 갖는지, 배율 계층이 무엇인지 정의합니다.
`engine`과 `storage`가 같은 상태를 다루므로 타입만 따로 뽑아 순환 참조를 막았습니다.

### `src/storage/` — 저장과 복구 (6파일, 테스트 3개)

**하는 일:** 세이브가 깨져도 진행이 날아가지 않게 지킵니다.
이중 백업 저장 순서(`saveManager.ts`), 버전 변환(`migrations.ts`),
언제 저장할지 판단(`autosave.ts`), 그리고 AsyncStorage를 감싼 인터페이스(`adapter.ts`)입니다.

**규칙:** 화면은 AsyncStorage를 직접 만지지 않고 `storage/index.ts`만 씁니다.
`adapter.ts`에 메모리 구현체가 함께 있어서 저장 로직을 기기 없이 테스트할 수 있습니다.

**여는 때:** 세이브 포맷을 바꿀 때(마이그레이션 필수), 복구 동작을 고칠 때.

### `src/state/` — 게임 루프 (2파일, 테스트 4개)

**하는 일:** 초당 10회 도는 게임 루프를 React **바깥**에서 돌립니다.

- `gameStore.ts` — 루프, 저장 시점, 앱 생명주기. React에 의존하지 않아 테스트가 쉽습니다.
- `GameContext.tsx` — 화면이 값을 구독하는 훅(`useGameValue`).

**여기가 이 앱 성능의 핵심입니다.** 루프가 상태를 매번 갱신하면 타격할 때마다
화면 전체가 다시 그려집니다. 대신 각 컴포넌트가 필요한 값만 고르고, **고른 값이 실제로
바뀔 때만** 그 컴포넌트가 다시 그려집니다.

**여는 때:** 루프 주기·저장 시점 변경, 화면이 과하게 다시 그려질 때.

### `src/screens/` — 화면 (10파일)

탭 5개(대장간·상점·주문·업적·기록)와 곁화면 5개(설정·공방·환생 모달·오프라인 복귀 모달·튜토리얼 오버레이)입니다.

**규칙:** 화면은 계산하지 않습니다. `engine`과 `state`가 준 결과를 배치하고 그릴 뿐입니다.
화면 안에 수식이 보이면 `engine`으로 옮길 신호입니다.

**여는 때:** 레이아웃·문구·화면 흐름 변경.

### `src/components/` — 공통 UI와 도트 렌더러 (11파일)

두 종류가 섞여 있습니다.

1. **공통 UI** — `index.tsx`(텍스트·버튼·패널), `ResourceHeader`, `Toast`, `WorkshopButton`.
   접근성 기본값(터치 영역 48, 스크린 리더 레이블)을 컴포넌트 자체에 넣어 화면마다
   챙기지 않아도 되게 했습니다.
2. **도트 렌더러** — `PixelCanvas`(픽셀을 정수 크기 View로 찍어 보간을 없앰),
   `AnimatedSprite`, `HitSpark`, `ForgeWorker`, `CoalForgeSprite`, `PixelBackground`,
   `spritePhase.ts`(여러 스프라이트의 박자를 맞추는 기준 시각).

애니메이션 상태는 각 잎 컴포넌트 안에만 두어 바깥 화면이 다시 그려지지 않게 합니다.

**여는 때:** 버튼·패널 같은 공통 요소 수정, 도트가 뭉개지거나 애니메이션이 어긋날 때.

### `src/services/` — 플랫폼에 닿는 부분 (3파일)

사운드(`sound.ts`), 햅틱(`haptics.ts`), 분석·광고·결제 인터페이스(`index.ts`)입니다.
**인터페이스를 먼저 두고 비활성 구현체를 쓰는** 방식이라, 실기기가 없어도 나머지가 전부 돌아갑니다.

**여는 때:** 소리·진동을 붙이거나 끌 때, 분석 이벤트 추가.

### `src/theme/` — 보이는 것의 규칙 (2파일)

- `index.ts` — 색 팔레트, 타이포, 간격, 최소 터치 크기
- `pixel.ts` — 도트 그리드 기준(아이콘 16/24, 오브젝트 32, 배경 320×180)과 **정수 배율만 허용**하는 규칙

`getPixelScale`이 1x·2x·3x·4x만 돌려주므로 1.5x 같은 소수 배율이 타입 수준에서 막힙니다.

**여는 때:** 색·글자 크기·여백 변경. 개별 화면에 색을 직접 적지 말고 여기서 가져다 씁니다.

### `src/navigation/` — 뒤로가기 규칙 (1파일)

`backExit.ts`는 "두 번 눌러 종료"의 시간 판정만 담습니다.
어떤 화면에서 어디로 물러날지는 `App.tsx`가 압니다 — 시간 판정만 떼어 두면 화면 없이 테스트할 수 있습니다.

## 루트와 그 밖의 폴더

| 위치 | 하는 일 |
|---|---|
| `App.tsx` | 앱 조립. 탭 5개 등록, 모달 표시 여부, 서비스와 저장소를 스토어에 연결 |
| `index.js` | Expo 진입점. `App.tsx`를 등록만 합니다 |
| `scripts/` | **앱에 안 들어가는 개발 도구.** 효과음·음악·아이콘 생성, 밸런스 시뮬레이터, APK 빌드 스크립트. `lib/`는 생성기들이 공유하는 신디사이저와 PNG 인코더입니다 |
| `assets/` | **앱 번들에 들어가는 파일.** `sounds/` 효과음 7종, `music/` 화로 티어별 4곡, 앱 아이콘·스플래시. 대부분 `scripts/`가 생성합니다 |
| `art/` | 도트 작업용 원본 — Aseprite 팔레트(`.gpl`), 구도 가이드 이미지. **번들에 안 들어갑니다** |
| `docs/` | 계획서(모든 수치의 근거), `art/` 도트 제작 가이드, `legal/` 약관 초안 |
| `android/` | `expo prebuild`가 만드는 네이티브 프로젝트. 비어 있어도 정상이고 커밋하지 않습니다 |
| `app.json` · `eas.json` | Expo 앱 설정 · 빌드 프로필 |
| `tsconfig.json` · `babel.config.js` · `vitest.config.ts` | 타입 검사 · 트랜스파일 · 테스트 설정 |

## 이걸 바꾸려면 여기

| 하고 싶은 것 | 열 곳 |
|---|---|
| 업그레이드 가격·성장률 조정 | `src/data/balance.ts`, `src/data/upgrades.ts` → `npm run simulate`로 검증 |
| 업그레이드·주문·업적 추가 | `src/data/`의 해당 파일 (엔진은 대개 안 건드려도 됩니다) |
| 생산량 계산이 이상함 | `src/engine/production.ts` |
| 환생 보상이 이상함 | `src/engine/prestige.ts` |
| 오프라인 보상이 이상함 | `src/engine/offline.ts` |
| 세이브가 깨짐·마이그레이션 | `src/storage/saveManager.ts`, `src/storage/migrations.ts` |
| 화면이 버벅임 | `src/state/GameContext.tsx`의 구독 범위, `src/components/`의 애니메이션 |
| 화면 배치·문구 | `src/screens/` |
| 색·글자·여백 | `src/theme/index.ts` |
| 도트 그림 수정 | `src/data/sprites.ts` · `icons.ts` · `workers.ts` |
| 도트가 뭉개짐 | `src/theme/pixel.ts`(배율), `src/components/PixelCanvas.tsx`(렌더링) |
| 효과음·음악 교체 | `scripts/generate-sounds.mjs` · `generate-music.mjs` → `npm run audio` |
| 탭 추가·내비게이션 변경 | `App.tsx` |

## 새 코드를 어디에 둘지 고르는 법

1. **기기 없이 답이 나오는 계산인가?** → `engine/` (수치라면 `data/`)
2. **저장·복구에 관한 것인가?** → `storage/`
3. **루프나 구독에 관한 것인가?** → `state/`
4. **화면 하나에서만 쓰는가?** → 그 화면 파일 안
5. **여러 화면이 쓰는 UI인가?** → `components/`
6. **기기 기능(소리·진동·네트워크)에 닿는가?** → `services/`

새 파일을 `engine/`이나 `storage/`에 넣었다면 `index.ts`에 export를 추가해야
바깥에서 쓸 수 있습니다 — 공개 API를 한 곳으로 모으려는 장치입니다.

# 배경 도트 제작 가이드

계획서 4.6 "제작 방식 결정 필요 항목"에 대한 확정 내용입니다.
**결정: 직접 제작(Aseprite).** 2026-08-18.

이 문서는 그리는 사람이 이것만 보고 시작할 수 있도록 쓴 사양서입니다.

---

## 왜 배경만 남았나

아이콘·캐릭터·오브젝트 도트 54개는 이미 만들어져 있습니다. 문자 행렬로 코드에
직접 들어 있어(`src/data/`) 팔레트와 형태 언어가 이미 통일되어 있습니다.

| 그리드 | 개수 | 내용 |
|---|---|---|
| 16px | 22 | 업그레이드·업적 아이콘 |
| 24px | 25 | 공방 인물 프레임, 설비 |
| 32px | 7 | 화로·모루 등 오브젝트 |

배경만 코드로 찍을 수 없습니다. 320×180은 57,600픽셀이라 픽셀마다 `View`를
만드는 `PixelCanvas` 방식으로는 감당이 안 됩니다. 그래서 배경은 **PNG 파일**로
만들고, 앱은 별도의 이미지 경로로 그립니다.

## 캔버스 사양

| 항목 | 값 |
|---|---|
| 크기 | **320 × 180 px** (계획서 4.6 기준 해상도) |
| 색 모드 | RGBA (투명 사용 가능) |
| 팔레트 | `art/moru-keugi.gpl` — Aseprite에서 불러와 씁니다 |
| 내보내기 | PNG, 배율 **1x**(원본 크기 그대로) |
| 저장 위치 | `assets/backgrounds/` |

### 배율에 대해

**반드시 1x 원본으로 내보냅니다.** 확대는 앱이 정수 배율로 처리합니다.
미리 2x·3x로 키워서 내보내면 앱이 다시 배율을 계산하면서 도트가 뭉개집니다.

원본 파일(`.aseprite`)은 `art/`에 함께 두면 나중에 수정할 때 편합니다.
`art/`는 앱 번들에 들어가지 않습니다.

## 파일 이름

화로 티어 4단계와 1:1로 대응합니다. 이름을 정확히 지켜야 코드가 찾습니다.

| 파일 | 티어 | 화로 이름 | 강조색 | 분위기 |
|---|---|---|---|---|
| `assets/backgrounds/forge_tier_0.png` | 0 | 초심자의 화로 | `#ff7a3d` 주황 | 낡은 오두막. 판자벽, 흙바닥, 작은 창. 소박하고 손때 묻은 느낌 |
| `assets/backgrounds/forge_tier_1.png` | 1 | 타오르는 화로 | `#d1450f` 진한 주황 | 석조 대장간. 돌벽과 아치, 도구가 늘어난 벽 |
| `assets/backgrounds/forge_tier_2.png` | 2 | 작열하는 용광로 | `#e0b479` 금빛 | 왕실 대장간. 높은 천장, 기둥, 금속 장식과 깃발 |
| `assets/backgrounds/forge_tier_3.png` | 3 | 용염의 성화 | `#cfe6ff` 하늘빛 백광 | 용의 대장간. 거대한 구조물, 신비로운 빛, 비늘·뼈 모티프 |

## 그릴 때 지킬 것

1. **1px 외곽선, 제한된 팔레트.** 계획서 4.6의 라인 규칙입니다. 기존 54개도
   전부 이 규칙을 따릅니다.
2. **팔레트 밖 색을 쓰지 않습니다.** 특히 배경 바탕은 `#150f0c`에서 크게
   벗어나지 않아야 그 위에 놓이는 인물·설비 도트가 읽힙니다.
3. **강조색은 티어 색만.** 각 장은 위 표의 강조색 계열만 씁니다. 티어가 오를 때
   같은 공간이 색으로 변해 가는 것이 이 게임의 성장 연출입니다.
4. **가운데 아래를 비웁니다.** 그 위에 모루·인물·설비가 올라갑니다. 배경에
   디테일을 몰아넣으면 실제 게임 요소가 묻힙니다.
5. **위쪽은 벽, 아래쪽은 바닥.** 공방 화면은 비스듬한 부감이라 화면의 위아래가
   곧 앞뒤입니다. 바닥은 평면으로 읽혀야 합니다.

## 무드보드 (계획서 4.6 요구 항목)

실제 제작 착수 전 레퍼런스 3~5장을 `art/moodboard/`에 모아 방향을 고정합니다.
찾을 때 기준으로 삼을 것:

- 어두운 배경에 주황 광원 하나가 중심인 도트 씬
- 320×180 안팎의 저해상도에서 공간의 깊이가 읽히는 배경
- 같은 공간이 단계별로 화려해지는 성장형 연출 사례

## 앱에 붙이는 절차

**렌더 경로는 이미 만들어져 있고 실기기 검증까지 끝났습니다.** 다만 지금은 **꺼져 있습니다.**
`src/components/PixelBackground.tsx`의 `BACKGROUNDS` 네 자리가 모두 `null`이라
대장간 화면에는 모루만 보입니다.

검증용으로 넣었던 임시 그림은 시험 무늬(체커보드·세로줄)가 그대로 보여서 지웠습니다.
필요하면 아래 명령으로 언제든 다시 만들 수 있습니다.

```bash
npx tsx scripts/generate-placeholder-backgrounds.ts
```

### 그림이 나왔을 때

1. `assets/backgrounds/`에 아래 세 크기를 넣습니다.

   | 파일 | 크기 |
   |---|---|
   | `forge_tier_0.png` | 320 × 180 |
   | `forge_tier_0@2x.png` | 640 × 360 |
   | `forge_tier_0@3x.png` | 960 × 540 |

   Aseprite에서 1x·2x·3x로 각각 내보내되 **확대 방식을 nearest-neighbor로** 지정합니다
   (Aseprite 기본값입니다).

2. `PixelBackground.tsx`의 `BACKGROUNDS`에서 그 티어의 `null`을 `require`로 바꿉니다.

   ```ts
   require('../../assets/backgrounds/forge_tier_0.png'),
   ```

**파일과 이 목록은 항상 같이 움직여야 합니다.** `require`는 정적 경로여야 해서, 파일 없이
`require`만 남으면 번들이 깨집니다. 반대로 파일만 넣고 목록을 안 고치면 아무것도 안 보입니다.

한 장씩 켜도 됩니다. 켜지 않은 티어는 계속 바탕색만 남습니다.

### 검증된 사항 (2026-08-18, Pixel 8 에뮬레이터)

계획서 4.6이 Phase 4로 미뤄 둔 "React Native에서의 nearest-neighbor 실제 처리
방식"을 실기기에서 확인했습니다.

배율은 **dp가 아니라 기기 픽셀**로 골라야 합니다. Pixel 8은 420dpi = 2.625배라
dp로 정수 배를 골라도 화면에서는 소수가 되어 보간이 낍니다. 화면 픽셀을 직접
읽어 재 보니 원본에 두 가지뿐이던 색이 **열다섯 가지**로 늘어나 있었습니다.
픽셀 기준으로 고친 뒤에는 **중간값이 0칸**이 되어 1픽셀 격자가 그대로 살아납니다.

이 규칙은 `getBackgroundLayout()`에 있고 회귀 테스트로 고정해 두었습니다.
